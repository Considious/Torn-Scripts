`upstream.user.js` is the unchanged audit source and is never executed by SLINK. `capture.js` is generated by `tools/extract-kal.mjs` from unchanged upstream functions: attack identity, disclosure validation, equipment compaction, ammunition, logs/travel context, capture payload, capture identity, Torn clock, request recognition, and rewritten-response recognition. The wrapper exports those functions without starting KAL’s own interface or authentication setup. Generated copies are also used in Torn-Scripts/SLINK-PDA.

SLINK changes are isolated in `kal-observer.js`, `kal-contributions.js`, the platform adapters, and its UI. Observation retains the original supported source: successful Torn `page.php?sid=attackData` fetch responses on a focused, user-opened attack page. It clones responses and does not rewrite Torn state. NPC exclusions and one eligible capture per attack view match upstream. Bonuses, raw exact-item data, ammo, timestamps, and unknown fields within item records remain intact. No mini-profile, target discovery, or mugging integration is added.

Uploads retain `POST https://kalends.dev/api/script/upload-loadout`, JSON `{key, version: "1.3.3", ...capture}`, and upstream `capture_id`. The public read API uses `Authorization: ApiKey ...`. The script upload protocol uses a key in its JSON body; SLINK does not change it to an unconfirmed header. `payload_source` retains upstream `native`/`rewritten` meaning. No client/source/comment property or custom header is added. The public API does not document a collector endpoint or SLINK identity; confirm extensions with Kalends before changing this protocol.

Local storage and retry handling differ deliberately: pending state is durable, retries are bounded to four total attempts, retry guidance is respected, and observations expire from automatic retry after 24 hours. Unacknowledged/ambiguous submissions become `uncertain` and are not replayed automatically. Acknowledged submissions discard their payload and retain a bounded deduplication tombstone. Queue limits: 100 records and 256 KiB; full/corrupt/quota-failed storage fails before upload. No upload identity is invented.
