# PDA 0.4.113 emergency startup/performance hotfix

Update the existing script in place; do not uninstall it or clear app data. A valid cached runtime starts immediately. Update discovery checks only the source manifest, at most once per15minutes; a discovered new revision is fetched on the next normal page load. Cold/update loading uses two workers and tries the same public source files on jsDelivr when raw GitHub is refused or times out. Keys/settings/targets are never sent to that mirror. Cache replacement still requires successful runtime readiness. A failed update can use the retained working cache. No cache plus both hosts unreachable means SLINK cannot start; the retry control leaves Torn usable.

The Xanax helper no longer rescans for unrelated attack text, skips energy searches when no Xanax action exists, and pauses its decoration observer while hidden. A real click still reads current energy and asks for confirmation. No settings, credentials, storage keys, cloud-restore behavior, permissions or assets were changed.

Checks: test-loader-recovery.mjs, test-dom-performance.mjs and complete build.mjs --check pass. Actual Edge MutationObserver fixture confirms zero whole-document rescans across unrelated attack frames, current-energy confirmation and hidden/resume. Public fallback manifest returned HTTP200. Physical PDA app/network acceptance remains needed. Stable extension0.19.13 carries related focused-window/profile/chat/Xanax changes. Audit work is not promoted by this release.
